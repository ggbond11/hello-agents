# 第一章 初识智能体

> 本章围绕“智能体是什么、如何运行、如何构建以及如何应用”展开，建立对 LLM 驱动智能体的基础认知。
>
> 参考：[Hello-Agents 第一章：初识智能体](https://datawhalechina.github.io/hello-agents/#/./chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93)

## 一、什么是智能体

智能体（Agent）是能够通过**传感器感知环境**，并通过**执行器自主采取行动**，以达成特定目标的实体。其基本组成包括：

- **环境（Environment）**：智能体所处的外部世界，例如道路交通、金融市场或互联网服务。
- **传感器（Sensors）**：获取环境信息的渠道，例如摄像头、麦克风、雷达、用户输入和 API 返回值。
- **执行器（Actuators）**：对环境施加影响的手段，例如机械臂、方向盘、代码执行器和外部服务调用。
- **自主性（Autonomy）**：根据感知信息和内部状态独立决策，而不是只执行固定脚本。

因此，智能体的核心是一个“**感知 → 决策 → 行动 → 获得反馈**”的闭环。

## 二、智能体的发展与类型

### 2.1 传统智能体的演进

传统智能体的能力主要依赖人工设计的规则、模型或目标函数，大致经历了以下演进：

1. **简单反射智能体**：依据当前输入执行“条件—动作”规则，没有记忆和预测能力，例如传统恒温器。
2. **基于模型的反射智能体**：维护内部世界模型，利用历史信息推断不可直接观察的环境状态，例如在隧道中仍能估计前车位置的自动驾驶系统。
3. **基于目标的智能体**：围绕目标选择行动并进行规划，例如 GPS 根据目的地规划路线。
4. **基于效用的智能体**：为不同结果评估效用，在时间、成本、舒适度等相互冲突的目标之间进行权衡。
5. **学习型智能体**：通过环境反馈和经验改进策略，强化学习是其代表方法；AlphaGo Zero 展示了通过自我对弈获得策略的能力。

### 2.2 大语言模型驱动的新范式

以 GPT 为代表的大语言模型（LLM）通过海量数据预训练获得隐式的世界知识和语言推理能力。与传统智能体相比，LLM 智能体通常具有：

- **更通用的自然语言交互能力**：能理解高层级、模糊且包含上下文的目标。
- **更灵活的任务分解与规划能力**：可将复杂目标拆解为多个子任务。
- **工具使用能力**：能根据需要调用搜索、代码解释器、数据库或业务 API。
- **上下文理解与动态修正能力**：根据用户反馈和工具结果调整后续计划。
- **神经与符号的结合**：LLM 的神经网络负责模式识别和语言生成，同时通过结构化的计划、思想和 API 调用进行符号化行动。

例如，用户说“规划一次厦门之旅”，LLM 智能体可以依次确认偏好、查询目的地和天气、制定行程，并在预算变化后重新筛选酒店，而不需要为每种情况编写固定规则。

### 2.3 三个互补的分类维度

**按内部决策架构分类**：反应式、模型式、基于目标、基于效用，以及具备自我改进能力的学习型智能体。

**按决策时间与反应性分类**：

- **反应式智能体**：响应快、开销低，但缺少长远规划，适合安全气囊等实时场景。
- **规划式（审议式）智能体**：行动前分析多种可能性，适合商业计划和长途旅行规划，但时间和计算成本较高。
- **混合式智能体**：结合即时反应与长远规划。现代 LLM 智能体通常通过“思考—行动—观察”的微循环兼顾二者。

**按知识表示分类**：

- **亚符号主义/连接主义**：知识隐含在神经网络参数中，擅长从数据识别模式，但可解释性较弱，可能产生幻觉。
- **符号主义**：知识表示为规则、概念和知识图谱，推理透明可解释，但面对未覆盖的现实情况较脆弱。
- **神经符号主义**：结合神经网络的模式识别与符号系统的逻辑推理。LLM 智能体可视为一种实践形式：用神经网络理解和生成语言，再以计划、函数调用等结构化符号与环境交互。

## 三、智能体的构成与运行原理

### 3.1 用 PEAS 描述任务环境

理解智能体首先要定义任务环境。PEAS 是描述任务环境的框架：

- **P（Performance）性能度量**：怎样判断任务完成得好，例如行程满意度、成本和安全性。
- **E（Environment）环境**：智能体工作的世界，例如航班、酒店、天气和景点服务。
- **A（Actuators）执行器**：智能体能做什么，例如查询、预订、发送消息或调用 API。
- **S（Sensors）传感器**：智能体能观察到什么，例如用户指令、API 结果和环境反馈。

实际的 LLM 智能体环境往往具有以下特点：

- **部分可观察**：智能体只能通过工具获得局部信息，因此需要记忆和探索。
- **随机或不确定**：同一查询的价格、库存等结果可能变化，需要监控和及时决策。
- **多智能体**：其他用户、脚本或系统的行为会改变环境。
- **序贯且动态**：当前行动会影响未来，环境也可能在决策过程中持续变化。

### 3.2 Agent Loop：智能体循环

智能体不是一次性生成答案，而是持续与环境交互。典型循环如下：

```text
感知 Observation
    ↓
思考 Thought：理解状态、规划任务、选择工具
    ↓
行动 Action：调用工具或执行操作
    ↓
环境状态改变并返回新的 Observation
    └─────────────── 循环 ───────────────┘
```

“思考”阶段通常包括：

1. **规划（Planning）**：结合当前观察和记忆，分解目标、制定或调整计划。
2. **工具选择（Tool Selection）**：选择下一步工具并生成正确的调用参数。

### 3.3 Thought-Action-Observation 交互协议

为了让 LLM 的输出能够被程序执行，需要使用结构化协议：

```text
Thought: 用户想知道北京的天气，我需要调用天气查询工具。
Action: get_weather(city="北京")
Observation: 北京当前天气为晴，气温 25 摄氏度，微风。
```

其中：

- **Thought** 是对当前情境的分析、规划和下一步决策。
- **Action** 是需要解析器执行的具体动作，通常表现为函数调用。
- **Observation** 是工具执行后返回、经过整理并反馈给模型的新信息。

外部解析器捕获 `Action` 后调用工具，再将工具返回的原始数据（如 JSON）整理为清晰的 `Observation`，供下一轮推理使用。循环持续到模型输出 `Finish[最终答案]` 为止。

## 四、5 分钟构建一个智能旅行助手

案例目标：查询北京当天的天气，再根据天气推荐旅游景点。这个案例集中体现了智能体的四项能力：**任务分解、工具调用、上下文理解、结果合成**。

### 4.1 构建步骤

1. **准备依赖**：使用 `requests` 访问网络，使用 `tavily-python` 搜索信息，使用 `openai` 或兼容 OpenAI 接口的 SDK 调用模型。
2. **设计系统提示词**：明确角色、可用工具、`Thought`/`Action` 输出格式，以及何时使用 `Finish` 结束任务。
3. **实现工具**：例如 `get_weather(city)` 查询天气，`get_attraction(city, weather)` 根据天气搜索景点，并将工具放入 `available_tools` 字典。
4. **接入模型**：通过兼容 OpenAI API 的客户端连接模型，需要配置 `API_KEY`、`BASE_URL` 和 `MODEL_ID`。
5. **执行行动循环**：将用户请求、历史观察和系统提示词交给 LLM；解析模型的 Action、调用对应工具、追加 Observation，直到任务完成。

### 4.2 案例执行过程

```text
用户：查询今天北京的天气，并根据天气推荐景点。

第 1 轮
Thought：先获取天气，再根据天气推荐景点。
Action：get_weather(city="北京")
Observation：北京晴，26℃。

第 2 轮
Thought：天气晴朗且温度适中，可以推荐户外景点。
Action：get_attraction(city="北京", weather="Sunny")
Observation：推荐颐和园或长城。

第 3 轮
Action：Finish[今天北京晴朗，26℃，适合游玩，推荐颐和园或长城。]
```

关键不在于写死“晴天就推荐颐和园”，而在于让模型根据实时观察结果自主决定下一步行动。

## 五、智能体的应用协作模式

### 5.1 作为开发者工具

在这种模式下，智能体嵌入人的工作流，增强而不是取代开发者，负责代码补全、问答、重构、测试和调试等重复或辅助性工作。代表性工具包括：

- **GitHub Copilot**：编辑器内的代码补全与对话式编程。
- **Claude Code**：在终端中理解代码库并执行编辑、测试、调试，也支持自动化场景。
- **Trae**：侧重代码生成、优化和快速原型开发。
- **Cursor**：AI 原生编辑器，强调全代码库上下文理解。

### 5.2 作为自主协作者

用户只提供高层目标，智能体负责规划、推理、执行和反思，直到交付结果。这种关系从“命令—执行”转向“目标—委托”。主要架构包括：

1. **单智能体自主循环**：通过“思考—规划—执行—反思”不断迭代完成开放目标。
2. **多智能体协作**：让不同角色的智能体进行对话或分工，例如 CAMEL 的角色扮演、CrewAI/MetaGPT 的组织化工作流，以及 AutoGen/AgentScope 的灵活对话网络。
3. **高级控制流架构**：以 LangGraph 为代表，用状态图表达循环、分支、回溯和人工介入。

### 5.3 Workflow 与 Agent 的差异

| 维度 | Workflow（工作流） | Agent（智能体） |
|---|---|---|
| 核心逻辑 | 预先定义步骤、顺序和条件 | 面向目标，自主决定步骤 |
| 行为方式 | 确定、静态、可预测 | 动态、可调整、具有一定自主性 |
| 决策来源 | 人工编排的规则和流程图 | LLM 对环境的理解、推理和规划 |
| 适用场景 | 规则明确、流程稳定的审批和自动化 | 目标开放、需要推理和工具使用的复杂任务 |
| 典型例子 | 费用报销：提交→审批→付款 | 查询天气→根据结果选工具→推荐景点 |

二者并非互斥：稳定、关键的步骤可以使用 Workflow 保证可靠性，开放和复杂的决策环节可以交给 Agent。

## 六、本章关键知识清单

- 智能体 = **感知环境 + 自主决策 + 采取行动 + 追求目标**。
- LLM 是智能体的“大脑”，工具、执行器和外部环境赋予它行动能力；只有模型本身并不等于完整智能体。
- 智能体的核心运行机制是 **Agent Loop**：感知（Observation）→思考（Thought）→行动（Action）→新观察。
- `Thought-Action-Observation` 是连接语言推理与程序执行的基本交互协议。
- PEAS 用于定义任务环境：性能度量、环境、执行器、传感器。
- LLM 智能体擅长将自然语言目标拆解为子任务、调用工具、利用上下文并动态修正计划。
- 传统 Workflow 强调预定义流程；Agent 强调面向目标的自主规划。工程实践中应根据任务的不确定性和可靠性要求组合使用二者。
