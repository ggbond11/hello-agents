## 一、语言模型要解决什么问题

**语言模型（Language Model，LM）**的基本任务是计算词序列出现的概率，或根据已有上下文预测下一个词元。给定句子 `S = (w₁, w₂, ..., wₘ)`，可以用概率链式法则表示：

```text
P(S) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · ... · P(wₘ|w₁,...,wₘ₋₁)
```

语言模型是智能体理解用户指令、生成自然语言、规划任务和调用工具的基础。模型本身并不是数据库式地“查找答案”，而是在上下文条件下估计并生成后续 Token。

## 二、从 N-gram 到 RNN/LSTM

### 2.1 N-gram 统计语言模型

直接估计完整历史条件概率会遇到数据稀疏问题，因为某个长词序列可能从未在训练语料中出现。N-gram 使用**马尔可夫假设**近似历史：一个词只依赖前面有限的 `N-1` 个词。

- **Bigram**：`P(wᵢ | wᵢ₋₁)`，只看前一个词。
- **Trigram**：`P(wᵢ | wᵢ₋₂, wᵢ₋₁)`，只看前两个词。

以 Bigram 为例，最大似然估计为：

```text
P(wᵢ | wᵢ₋₁) = Count(wᵢ₋₁, wᵢ) / Count(wᵢ₋₁)
```

N-gram 的优点是原理简单、容易实现；局限包括：

- **数据稀疏**：未出现过的词或词组概率为 0，需要平滑处理。
- **上下文有限**：只能利用固定窗口，无法有效捕捉远距离依赖。
- **泛化能力差**：把词视为离散符号，不能理解 `agent` 和 `robot` 这样的语义相似性。
- **参数规模受限**：增大 N 会带来组合数量和存储、估计成本的快速增长。

### 2.2 神经网络语言模型与词嵌入

Bengio 等人提出的前馈神经网络语言模型，用连续向量表示词，并学习从上下文到下一个词的映射：

1. **词嵌入（Word Embedding）**：将每个词映射为高维连续向量，使语义相近的词在向量空间中更接近。
2. **神经网络预测**：输入前 `N-1` 个词的向量，输出词表中下一个词的概率分布。

词向量可以使用**余弦相似度**衡量相似性：

```text
similarity(a, b) = (a · b) / (|a| |b|) = cos(θ)
```

向量表示还能学习类比关系，例如：

```text
vector("king") - vector("man") + vector("woman") ≈ vector("queen")
```

神经网络模型缓解了 N-gram 的离散表示和泛化问题，但固定上下文窗口仍然限制了对长文本的理解。

### 2.3 RNN 与 LSTM

**循环神经网络（RNN）**通过隐藏状态保存历史信息。处理每个时间步时，模型将当前输入与上一时刻的隐藏状态结合，生成新的隐藏状态并传给下一步，因此能够处理变长序列。

标准 RNN 的主要问题是长序列训练中的**梯度消失和梯度爆炸**：反向传播经过多个时间步时，梯度反复相乘，导致模型难以学习很久以前的信息，即长期依赖问题。

**长短时记忆网络（LSTM）**通过细胞状态和门控机制改善长期依赖：

- **遗忘门**：决定丢弃细胞状态中的哪些旧信息。
- **输入门**：决定将当前输入中的哪些信息写入细胞状态。
- **输出门**：决定根据细胞状态向隐藏状态输出哪些信息。

RNN/LSTM 能够保留序列记忆，但必须按时间顺序计算，难以并行训练，限制了训练速度和模型规模。

## 三、Transformer 架构

### 3.1 为什么需要 Transformer

RNN 按顺序处理 Token，第 `t` 步必须等待第 `t-1` 步完成，长序列训练效率低。Transformer 于 2017 年提出，抛弃循环结构，完全依靠注意力机制捕捉序列内依赖，从而可以并行处理序列，并更好地扩展到大规模训练。

原始 Transformer 采用 **Encoder-Decoder** 架构：

- **Encoder（编码器）**：读取完整输入，生成每个 Token 的上下文表示，负责“理解”。
- **Decoder（解码器）**：参考已生成内容和编码器输出，逐步生成目标序列，负责“生成”。

### 3.2 自注意力与多头注意力

**自注意力（Self-Attention）**让序列中的每个 Token 都能关注其他 Token，并根据关联程度聚合信息。每个输入向量经过三个可学习矩阵映射为：

- **Query（Q，查询）**：当前 Token 想获取什么信息。
- **Key（K，键）**：每个 Token 可被查询的特征。
- **Value（V，值）**：每个 Token 实际携带的内容。

缩放点积注意力公式为：

```text
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
```

计算步骤：

1. 由输入生成 Q、K、V。
2. 用 Q 与 K 的点积计算相关性分数。
3. 除以 `√dₖ` 稳定数值和梯度。
4. 用 Softmax 将分数转为注意力权重。
5. 对 V 加权求和，得到融合上下文的新表示。

**多头注意力（Multi-Head Attention）**将 Q、K、V 的维度切分成多个头，每个头独立学习一种关系，再拼接并线性变换。不同头可以分别关注指代、语法、时态、位置等不同关系，因此比单头注意力表达能力更强。

### 3.3 逐位置前馈网络

多头注意力负责从全序列聚合信息，**位置前馈网络（Position-wise FFN）**则对每个 Token 的表示独立进行非线性变换，且所有位置共享同一组参数：

```text
FFN(x) = ReLU(xW₁ + b₁)W₂ + b₂
```

通常先将维度从 `d_model` 扩大到 `d_ff`（例如 `4 × d_model`），经过激活后再映射回 `d_model`，以学习更丰富的高阶特征。

### 3.4 残差连接与层归一化

Transformer 子层通常使用 **Add & Norm**：

- **残差连接（Add）**：`Output = x + Sublayer(x)`，为梯度提供直接通路，帮助深层网络稳定训练。
- **层归一化（Norm）**：对单个样本的特征进行归一化，使数值分布更稳定，加快收敛。

### 3.5 位置编码

自注意力本身只计算 Token 之间的关系，不知道词元顺序。因此 Transformer 需要把位置信息加入词嵌入。经典 Transformer 使用正弦、余弦位置编码：

```text
PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))
```

这样，即使两个 Token 的词嵌入相同，处于不同位置时也会得到不同的最终表示。

## 四、Decoder-Only 与 GPT

GPT 将 Transformer 简化为只保留 Decoder 的 **Decoder-Only** 架构。其核心思想是：回答问题、写作和生成代码，本质上都可以归结为根据已有序列预测下一个 Token。

### 4.1 自回归生成

```text
输入起始文本
  ↓
预测下一个 Token
  ↓
将 Token 拼接回上下文
  ↓
再次预测下一个 Token
  ↓
重复直到结束
```

这就是**自回归（Autoregressive）**生成。训练时虽然可以并行输入整段文本，但模型不能偷看未来答案，因此使用**掩码自注意力（Masked Self-Attention）**：将当前位置之后的注意力分数置为负无穷，Softmax 后对应权重为 0。

### 4.2 Decoder-Only 的优势

- **训练目标统一**：只需在海量无标注文本上学习“预测下一个 Token”。
- **结构简单且易扩展**：减少组件后更适合规模化训练。
- **天然适合生成**：与对话、写作、代码生成等任务的生成过程一致。
- **适合作为智能体大脑**：可以接收上下文、生成计划、输出工具调用。

## 五、与大语言模型交互

### 5.1 提示工程

Prompt 是人与模型沟通的语言，**提示工程（Prompt Engineering）**研究如何设计清晰、有效的指令，使模型输出符合任务目标。一个好的 Prompt 通常应明确：角色、任务、背景、约束、输出格式和示例。

#### 采样参数

模型根据 Softmax 得到下一个 Token 的概率分布，再按照采样策略选择输出：

- **Temperature**：调节分布的平滑程度。
  - 低温度：输出更确定，适合事实问答、代码和严格格式。
  - 中温度：兼顾稳定与自然，适合一般对话和文案。
  - 高温度：更发散和有创意，但错误和不连贯风险更高。
- **Top-k**：只保留概率最高的 `k` 个 Token，再从中采样；`k=1` 时接近贪心生成。
- **Top-p（Nucleus Sampling）**：按概率排序，保留累计概率达到 `p` 的最小候选集合，能够动态适应分布的长尾。

实际使用时通常不必同时强烈调整所有参数。事实性任务应偏向确定性和低随机性，创意任务可适当提高多样性。

#### Zero-shot、One-shot、Few-shot

- **零样本（Zero-shot）**：只给任务指令，不提供示例。
- **单样本（One-shot）**：提供一个输入—输出示例，让模型模仿格式。
- **少样本（Few-shot）**：提供多个示例，帮助模型理解任务边界、格式和风格。

#### 常用提示技巧

- **角色扮演**：指定模型的身份、专业水平和回答风格。
- **上下文示例**：用输入—输出样例约束复杂格式，例如 JSON。
- **思维链（Chain-of-Thought，CoT）**：对数学、逻辑和多步骤任务，引导模型逐步分析，提高推理质量和可检查性。

### 5.2 指令调优

早期 GPT 主要是“文本补全”模型，擅长续写但不一定擅长遵循人类指令。**指令调优（Instruction Tuning）**使用大量“指令—回答”数据对预训练模型继续训练，使其更好地理解和执行自然语言任务。

预训练提供通用能力，指令调优改善交互和遵循指令的能力；ChatGPT、Qwen、DeepSeek 等面向用户的模型通常都经过了这类训练或类似的对齐过程。

## 六、文本分词与 Token

### 6.1 为什么需要分词

计算机最终处理的是数字，因此输入模型前必须把文本切分为 Token，并映射为 Token ID。分词器（Tokenizer）定义切分和编码规则。

- **按词分词**：直观，但词表巨大，容易产生未登录词（OOV），且 `look`、`looks`、`looking` 的关系难以共享。
- **按字符分词**：词表小且几乎没有 OOV，但单个字符语义弱，序列更长，学习效率低。
- **子词分词**：在词表规模和语义表达之间折中。常见词保留为整体，罕见词拆为多个可组合片段，是现代 LLM 的主流方式。

### 6.2 BPE、WordPiece 与 SentencePiece

**字节对编码（Byte-Pair Encoding，BPE）**的训练过程：

1. 以字符或字节作为初始词元。
2. 统计语料中相邻词元对的频率。
3. 合并出现频率最高的词元对，加入词表。
4. 重复合并，直到词表达到预设大小。

这样，即使遇到训练时没有见过的词，也可以拆成已知子词组合。

- **WordPiece**：BERT 使用的算法，与 BPE 类似，但更关注对语言模型概率的提升。
- **SentencePiece**：将空格视为普通字符（常用下划线表示），分词和解码可逆，也更适合不依赖空格的语言。

### 6.3 分词对智能体开发的影响

- **上下文窗口**按 Token 数计算，而不是字符数或单词数；不同语言和分词器的 Token 数可能差异很大。
- **API 成本**通常按输入和输出 Token 数计费，压缩提示和合理管理历史消息可以降低成本。
- **模型表现**可能受分词影响。标点、空格、大小写和罕见组合可能被切分成不同 Token，导致看似奇怪的结果。
- **长时记忆**需要精确控制 Token 长度，避免超出模型上下文窗口。

## 七、调用开源大语言模型

除了通过 API 调用模型，也可以使用 Hugging Face Transformers 在本地部署开源模型。教程以轻量级的 `Qwen/Qwen1.5-0.5B-Chat` 为例，基本流程如下：

```bash
pip install transformers torch
```

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "Qwen/Qwen1.5-0.5B-Chat"
device = "cuda" if torch.cuda.is_available() else "cpu"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).to(device)

messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "你好，请介绍你自己。"},
]
text = tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True
)
model_inputs = tokenizer([text], return_tensors="pt").to(device)

generated_ids = model.generate(
    model_inputs.input_ids,
    max_new_tokens=512,
)
new_ids = [
    output_ids[len(input_ids):]
    for input_ids, output_ids in zip(model_inputs.input_ids, generated_ids)
]
response = tokenizer.batch_decode(new_ids, skip_special_tokens=True)[0]
print(response)
```

要点：

1. `AutoTokenizer` 负责对话模板和 Token ID 编解码。
2. `AutoModelForCausalLM` 加载因果语言模型。
3. `apply_chat_template()` 将 system/user 等消息转换为模型规定的格式。
4. `generate()` 生成 Token ID。
5. `decode()` 将生成的 Token ID 转回人类可读文本。

本地部署的优点是数据隐私、离线运行和更强的自主可控性；代价是需要本地硬件、模型存储和运维能力。

## 八、模型选择

模型选型不是单纯追求参数规模，而是在能力、成本、速度和部署方式之间做权衡。主要考量因素包括：

- **能力与性能**：推理、代码、多语言、创作、多模态等能力是否符合任务需求。
- **成本**：闭源模型主要是 API 费用；开源模型还要考虑 GPU、内存和运维成本。
- **延迟**：客服、实时语音和游戏 NPC 等应用对响应速度敏感。
- **上下文窗口**：长文档、代码库和长期对话需要更大的 Token 容量。
- **部署方式**：API 使用简单但数据需发送给第三方；本地部署隐私和控制力更强。
- **生态与工具链**：社区、模型库、微调工具及与 Transformers、LangChain、LlamaIndex 等框架的兼容性。
- **可微调性**：特定领域任务是否能使用自有数据定制。
- **安全与伦理**：偏见、毒性、幻觉、隐私和合规风险。

总体上，闭源模型通常提供便捷稳定的 API 和较强的通用能力；开源模型则提供本地部署、透明度和定制自由。应以实际任务的评测结果为依据，而不是只看宣传或参数量。

## 九、缩放法则与模型局限

### 9.1 缩放法则

**缩放法则（Scaling Laws）**指出，在一定范围内，模型损失与参数量、训练数据量、计算量之间存在可预测的幂律关系。合理增加模型、数据和计算资源，性能通常会平滑提升。

Chinchilla 研究进一步强调：在固定计算预算下，模型参数量和训练数据量存在最佳配比；并非参数越多越好，较小但训练数据更充分的模型也可能超过更大的模型。因此，应重视**数据效率**和整体资源平衡。

当模型规模跨过一定阈值后，可能出现**能力涌现**，例如指令遵循、代码生成、思维链和多步推理。这意味着复杂智能体往往需要具备足够能力和规模的底层模型，但规模本身不等于可靠性。

### 9.2 模型幻觉

**幻觉（Hallucination）**指模型生成的内容与事实、输入或上下文不一致，或编造不存在的实体、引用和事件。常见类型包括：

- **事实性幻觉**：生成与现实事实不符的信息。
- **忠实性幻觉**：摘要、翻译等任务没有忠实反映原文。
- **内在幻觉**：生成内容与输入信息直接矛盾。

原因包括：

- 训练数据中存在错误、冲突或偏见。
- 自回归机制优化的是“下一个 Token 的可能性”，而不是内置的事实核查。
- 复杂推理链中可能出现计算或逻辑错误。
- 模型知识存在时间截止点，无法自动知道最新事件。

缓解方法：

1. **数据层面**：清洗高质量数据、引入事实知识、使用人类反馈强化学习等。
2. **模型层面**：改进架构，让模型表达不确定性。
3. **推理层面**：使用 RAG 检索外部知识，要求多步推理与验证。
4. **工具层面**：调用搜索引擎、计算器、代码解释器和业务 API 获取实时信息或精确结果。
5. **应用层面**：对高风险结果设置人工审核、来源引用和失败兜底。

智能体尤其需要重视幻觉，因为错误的工具调用、日期、价格、代码或实体可能直接影响外部环境。模型输出应被视为候选决策，而不是天然可信的事实。

## 十、本章关键知识清单

- 语言模型的核心任务是建模文本概率，并根据上下文预测下一个 Token。
- N-gram 通过有限历史近似语言概率，但存在数据稀疏、固定窗口和泛化不足问题。
- 词嵌入将离散词映射到连续向量空间，使模型能够学习语义相似性和类比关系。
- RNN 用隐藏状态传递序列信息；LSTM 通过细胞状态和门控机制缓解长期依赖问题。
- Transformer 用自注意力替代循环结构，支持并行计算，是现代 LLM 的核心架构基础。
- 注意力公式为 `softmax(QKᵀ / √dₖ)V`；多头注意力从不同表示子空间捕捉多种关系。
- Transformer 还依赖位置编码、逐位置前馈网络、残差连接和层归一化。
- GPT 采用 Decoder-Only 和自回归生成，通过掩码自注意力避免训练时看到未来 Token。
- Prompt 决定模型如何理解任务；Temperature、Top-k、Top-p 决定输出的确定性和多样性。
- Zero-shot、One-shot、Few-shot、角色扮演、上下文示例和思维链是常用提示方法。
- 分词把文本转换为 Token ID；BPE 等子词算法在词表规模、OOV 和语义表达之间折中。
- Token 数直接影响上下文窗口、API 成本、速度和模型表现。
- 模型选型应综合能力、成本、延迟、上下文、部署、生态、可微调性和安全性。
- 缩放法则说明规模、数据和计算会影响能力，但应关注参数与数据的最优配比。
- 幻觉是 LLM 的重要局限，RAG、工具调用、多步验证和人工审核可以提高智能体可靠性。
